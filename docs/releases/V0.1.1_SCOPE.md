## V0.1.1 work plan

1. **Scene lifecycle and privacy:** rename, duplicate, archive/restore, order, dimensions, camera settings, active player scene vs GM drafts, confirmation, and role-filtered scene/snapshot access.
2. **First-class scene model:** layers and editable scene objects, visibility/locking/z-order, with GM-only objects omitted from player API and socket projections.
3. **Grid and token workflows:** persisted grid appearance/offset/snap/scale, calibration preview and image-backed acceptance, token properties and safe versioned editing; define bounds for grouped operations/undo.
4. **Asset library and tabletop tools:** categorized searchable assets, safe multi-file ingest, reference-aware deletion, thumbnails, ruler, pointer, drawing, keyboard help and panel layout.
5. **Reliability/security:** evict revoked members from sockets, test concurrent/stale moves, event projections, malformed inputs, uploads, and secret-free logs.
6. **Verification and operations:** package-local Vitest suites without `--passWithNoTests`, PostgreSQL integration tests, two-context Playwright coverage, CI, measured performance, and consistent database/media backup restore.
7. **Playable demo and acceptance:** original 30–60 minute Amber Crossing scenario, documented local flow, screenshots, limitations, and owner review.

The scope is broad enough that work proceeds in dependency order and the acceptance report must identify any uncompleted rows. Do not describe a deferred feature as implemented. Future V0.2 scope remains walls, doors, lighting and fog of war, and is not part of this release.
