# Ручная приёмка V0.1.1

Для прохода нужны ведущий и минимум один участник. Используйте два изолированных браузерных профиля. Запишите SHA, версию браузера, разрешение, язык, ожидаемый результат и наблюдение для каждого шага. Запускайте на локальных тестовых данных.

## Запуск

1. Установите Node 24.13 и Docker. Выполните `corepack pnpm@12.23.0 install --frozen-lockfile`. Создайте локальный `.env` по `.env.example` и задайте `DEMO_PASSWORD` длиной от 12 символов.
2. Запустите `docker compose up -d db`, `corepack pnpm@12.23.0 db:migrate`, `corepack pnpm@12.23.0 db:seed`, затем `corepack pnpm@12.23.0 db:seed:playable-amber`. Запустите `corepack pnpm@12.23.0 dev`. Проверьте, что локальные порты из `.env` свободны. Vite должен проксировать точный адрес API.
3. Откройте `http://127.0.0.1:5173`. Войдите под локальным `demo@nri.local` с заданным паролем. Создайте отдельную копию **Amber Crossing: The Lantern Vault** через кнопку копирования. Исходная кампания остаётся заготовкой для следующих проходов.

## Игровая сессия

| Шаг | Что должно наблюдаться |
| --- | --- |
| Первый запуск | В третьем чистом профиле можно зарегистрироваться, создать пустую кампанию, добавить сцену и загрузить оригинальный PNG/JPEG/WebP |
| Карта и сетка | Два отмеченных пункта и число ячеек дают превью. Сохранённые масштаб и смещение восстанавливаются после обновления |
| Приглашение | Player регистрируется по ссылке в своём профиле, видит активную сцену и открытые токены. Черновики, скрытые слои и заметки ведущего отсутствуют |
| Персонажи | Назначить Player владельцем Mira, переместить токен, изменить видимый ресурс. Другой участник видит движение. Заметка владельца доступна адресату |
| Общение | Отправить общий и приватный чат, бросить публичный и скрытый кубик. Частные сведения видны соответствующим адресатам |
| Инструменты | На Blueglass Lane провести маршрут от трактира. Опробовать кисть, линейку, панорамирование, масштаб, общий указатель и выбор токенов |
| Редактирование | Скопировать два объекта, вставить, отменить и повторить. Проверить Undo/Redo перемещения, размера, поворота и удаления. При более свежем изменении из другого GM-сеанса группа сохраняется целиком |
| Бой | Активировать Vault, начать инициативу, перейти к следующему ходу, завершить бой. Сравнить GM/Player-проекции скрытого участника |
| Возобновление | Отключить интернет в одном профиле, вернуть сеть, затем войти повторно. Активная сцена, история чата и сохранённые позиции восстанавливаются |
| Доступ | Понизить второго GM до Player и убрать участника. Проверить обе открытые вкладки и новое подключение |
| Интерфейс | Проверить 1366×768, 1920×1080 и 2560×1440 в обеих ролях. Переключить EN/RU, тему и fullscreen, проверить управление Tab и Ctrl+Z внутри текстового поля |

Сюжет и подсказки ведущего доступны в [AMBER_CROSSING_PLAY_GUIDE.md](../demo/AMBER_CROSSING_PLAY_GUIDE.md). Для отчёта отдельно отметьте пройденные шаги и препятствия игре. Статус `ACCEPTED` требует решения владельца после совместной сессии.
