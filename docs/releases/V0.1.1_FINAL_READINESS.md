## Локальные результаты OPS

- Restore из копии `ops-acceptance-20261128`. Создание и сверка backup с остановкой писателей заняли 1,99 с. Пустой проект достиг readiness за 23,57 с. Архив БД 71 857 байт, вместе с 20 файлами media 576 829 байт. Из 16 исходных изображений совпали все. Четыре сохранённых thumbnail совпали, двенадцать превью Amber строятся по запросу. Активная инициатива, версии, роли, скрытый бросок и действующий receipt остались пригодны для продолжения игры.
- Prune удалил один просроченный receipt, повтор удалил ноль. Сохранились восемь действующих receipts, девять записей чата, четыре броска и 27 токенов в проверенном снимке. При остановленной БД команда с `--no-deps` вернула ошибку без данных подключения. После запуска базы повтор прошёл. Шаблоны systemd готовы к настройке на согласованном хосте. [Инструкция](../operations/PERF_GPU_OPS_HANDOFF.md#daily-rest-receipt-pruning)
- Инвентаризация исходников и preview работает в режиме чтения. В восстановленной копии нет пропавших исходников, orphan и staging-файлов. На отдельной копии найдены один потерянный оригинал, один файл без строки, один повреждённый thumbnail и по одному свежему и старому staging.
- При отказе БД readiness вернул 503 примерно за 5 с, `/api/health` остался доступен. Защищённые чтения, запись и WSS reconnect отказали. После запуска PostgreSQL readiness вернулся за 301 мс с тем же процессом API. Ошибка команды не привела к частичной записи, повтор создал одну сущность. Для неотвечающих WebSocket-клиентов Docker до исправления исчерпал 25 с и завершил Node с кодом 137. После исправления Node завершился с кодом 0 за 5,50 с, полный цикл перезапуска занял 8,02 с. Сценарий повторяется в CI на Ubuntu.
- Windows 11, Node 24.13.0. Прямой API `35080`, родитель `9508`, дошёл до готовности и владел портом 35612. Playwright CLI `14320` запустил worker `37264`. Worker остановил исходный API и запустил `33560` с `dist/index.js` из `apps/server`. В восьми снимках процессов зафиксирован владелец исходного порта и отсутствие listener у дочернего процесса. После двух сообщений dotenv отсутствовали маркеры завершения импорта, создания маршрутов/Socket.IO и HTTP. `/api/health` оставался недоступен в пределах 45 секунд. Отдельный Node-parent `38192` поднял то же приложение и БД дочерним процессом `32200` за 1,30 с. Принудительное завершение двух дочерних процессов отражалось как SIGTERM без кода. Linux graceful shutdown проверен отдельно. Протяжённый Windows-тест жестов под параллельной нагрузкой дважды истёк по общему лимиту 150 секунд. Запуски Windows остаются открытым риском. [Порядок диагностики](../operations/PERF_GPU_OPS_HANDOFF.md)

## Что необходимо от владельца

1. Выбрать физический или виртуальный хост для приватной альфы и допустимый способ подключения участников.
2. Указать адрес, которому будет соответствовать TLS-сертификат, и способ доверия к нему на клиентах.
3. Выбрать два независимых клиентских устройства или профиля, указать браузеры и разрешения.
4. Выбрать GPU для следующего замера и согласовать игровой предел для тяжёлых сцен по результатам фактического теста.
5. Назначить ведущего и двух игроков и выделить 30–60 минут. После сессии записать PASS/FAIL/NOT_TESTED и решение о выпуске.
