# CMD-ACL authorization matrix

**Status:** `AUTOMATED_TESTS_PASSED`; the implementation tree at `93f48fa8746bbdb4634b60bd6d3683a607fcf8ca` passed Ubuntu 24.04 CI #196, including Playwright 9/9. A later documentation-only commit records this status. This evidence does not replace V0.1.1 manual acceptance or operational gates.
**Scope:** 40 registered routes in the token, scene, campaign, membership/invitation, and asset route modules, including dynamic token delete/restore registrations; command authorization, coupled audit writes, and protected resource reads. This matrix does not reopen the completed RT-ACL event-delivery design.

## Shared transaction rules

For a command that changes campaign state, the implemented order is **session → campaign → membership(s) → scene/folder/resource → dependent rows**, with multiple row IDs sorted before locking. Lock strength is selected to serialize with campaign archive/restore and role changes. Each mutation inserts its required audit row before the same transaction commits. Realtime publication and room eviction occur only after commit and use the existing audience-filtered publishers. A request that loses the race to logout, membership removal, demotion, archive, or a version change is rejected without committing the command.

The filesystem is not part of PostgreSQL's transaction. Uploads are decoded and written to private staging files before acquiring command locks; the transaction rechecks access and references, inserts metadata/audit, and renames staged files. SQL failure triggers best-effort removal of staged/final files. Campaign duplication uses copied storage keys and compensation around the database transaction. These are compensating workflows, not cross-system atomic transactions. A process crash between rename and SQL commit can leave an orphan file; a crash after commit may leave the committed asset even if the caller never received its response. No durable filesystem journal exists in this release.

## Known limits and completion evidence

- `GET /api/scenes/:sceneId/tokens`, campaign scene lists, token trash and media are the protected reads changed or reviewed for this package. Scene layers/objects, token notes and archived-scene projections remain owned by their existing object-lifecycle and private-channel transactions; their existing PostgreSQL and Playwright suites must still pass.
- A currently open file descriptor can continue streaming bytes after authorization locks are released. No bytes are sent before authorization, but bytes already sent or buffered cannot be recalled after revocation.
- Filesystem cleanup is best effort. The test-only `x-nri-test-asset-fault` hook is inert unless `NODE_ENV=test`; it is not an operational recovery queue.
- The new real-PostgreSQL runner passes 20 scenarios, including campaign-audit rollback, invite expiry and creator demotion, upload authorization races against membership demotion and campaign archive, seven staged/SQL/rename fault injections, hidden and cross-campaign original/thumbnail denial, and five-sample local HTTP/event measurements. Those measurements omit SQL count and lock-hold data. All legacy PostgreSQL suites passed after the latest route/test changes. Ubuntu 24.04 CI [#196](https://github.com/Jerry93Sky/NRI/actions/runs/46014338206) passed, including Playwright 9/9. The same suite is 8/9 on Windows: API restart recovery failed because the spawned `dist/index.js` did not become ready after SIGTERM. CMD-ACL is `AUTOMATED_TESTS_PASSED`; local file cleanup remains best-effort and crash recovery is not journaled. These limits and automated status do not imply owner acceptance of V0.1.1.
