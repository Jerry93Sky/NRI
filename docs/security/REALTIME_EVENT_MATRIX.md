Baseline `7fd3d6bebe44383b55a1e0038a79ef9d94cf0d7c`, CI #192. This inventory covers **24 distinct outbound application event names** across all server emit sites. Acknowledgements, Socket.IO control packets and room joins/leaves are transport or routing operations.

`C` is the campaign room, `G` its manager room, `M` its per-member room and `U` a user's personal room. `DB` means recipient sessions, membership and roles are locked and checked in PostgreSQL at publication. `Room` means receipt relies on subscription and eviction, including handshake and expiry handling, without a fresh database check for every event. An actor check alone does not authorize the recipient. “Separate audit” means the audit record has a different commit boundary.

## Confirmed gaps in scene content

- The object/layer create routes selected role and scene before writing. Object creation read layer lock and visibility independently of insertion. The stored object could therefore be written after the checked access state changed. Row and audit also had separate commits.
- Object edit/copy and layer edit/delete committed before their emits. They routed captured data through rooms without re-reading layer visibility or the recipient's current database authorization. Copy used its earlier destination snapshot. Object edits formed removal and update packets from the command's snapshots.
- Layer hide supplied an ID-only invalidation. The web client already loads fresh snapshots on object and layer events and scopes results by workspace and latest request. Existing events therefore support invalidation without a wire redesign. A future delivery path must still prevent disclosure in the packet itself.

## Delivery after stabilization

| Events | Checks, persistence and evidence now |
| --- | --- |
| `scene:object_created`, `scene:object_updated` | Create, copy, edit and move now publish after an audited commit. Session, membership, role and scene are rechecked in PostgreSQL and locked with the relevant layers and objects. Positive packets use the committed revision if it is still current, with distinct manager and Player projections. Player authorship is a viewer-specific boolean. Post-commit permission/visibility, stale revision and failed-write regressions cover these paths |
| `scene:object_deleted` | Object changes that removed a formerly public projection send only its scene and object IDs to Players if the object is still inaccessible. Lifecycle notifications also use the live scene audience. Tests cover all move transitions, another private edit after hiding and a pending update followed by deletion |
| `scene:layer_created`, `scene:layer_updated`, `scene:layer_hidden`, `scene:layer_deleted` | All have audited transactions. They recheck current session, membership, role, scene and layer. A current public layer sends its metadata, while hide and delete expose only IDs with prior public visibility. Reopening invalidates the authorized snapshot so Players see only current visible objects. Tests cover rename, sort, lock, hide, reveal, deletion and fast transitions |
| `token:moved`, group token events, object lifecycle restore/delete | Share the scene audience acquisition with ordinary scene content. The 23 movement and 28 lifecycle regressions retain their previous scope |

The authorization locks stay held through synchronous Socket.IO enqueue. Session expiry and the local subscription are checked at each scene-content send. After enqueue, a packet may travel or sit in a transport buffer while permissions change. The server cannot recall bytes that have left the process. Delivery is best effort on a single API instance. Reconnect and scope changes use authorized snapshots. [Protocol](../architecture/REALTIME_PROTOCOL.md) · [Performance](../performance/SCENE_REALTIME_PROFILE.md)

## RT-ACL completion — current delivery

Membership and campaign notifications remain intentionally small control signals; the client reloads current state instead of trusting a role, permission or archive packet. “No leak” below means the listed regressions passed, not a claim about queued packets already handed to Socket.IO or data a user previously viewed.

## Event class and delivery contract

**CMD-ACL writer update:** Current token create/copy and scene settings/background writers persist their required audit in the same transaction as the mutation and invoke existing publishers after commit. The baseline columns above preserve historical findings; the endpoint matrix records current lock order and remaining verification status. This update does not change RT-ACL recipient guarantees.

| Class | Events | Contract and evidence |
| --- | --- | --- |
| Persistent state | `scene:object_*`, `scene:layer_*`, `token:created`, `token:updated`, `token:moved`, `token:hidden`, `scene:updated`, `scene:activated`, `initiative:*` | Authorized projection after commit where the writer is transactional; current revisions and scene visibility are re-read. Scene activation/settings are invalidations for authorized REST snapshots. PostgreSQL lifecycle, movement, private-channel and RT-ACL suites; browser snapshot/privacy flows |
| Private append-only | `chat:message`, `chat:private`, `dice:result` | Legal append and current event audience, authorized history for chat, hidden dice manager projection. No automatic retries; duplicate client submissions can append. PostgreSQL private-channel suite and multiplayer smoke |
| Ephemeral | `scene:pointer`, `presence:joined` | Bounded, transient payload, current sender check and active-scene/draft rule for pointers. 50 ms per-socket throttle, 1200/minute command limit, 1.6 s client pointer expiry. Reconnect does not replay them. PostgreSQL barriers and loopback pointer profile |
| Control/invalidation | `membership:changed`, `membership:removed`, `campaign:archived`, `campaign:drawing_permission`, plus scene invalidations | Minimal payloads. Clients query current role, campaign, drawing permission and scene snapshots. Removed-member signal intentionally targets personal sockets. Browser removal/rejoin barrier and current API checks |

The current pointer microprofile runs over local HTTP/WebSocket and PostgreSQL; it does not establish WAN or production capacity. API process CPU and endpoint RSS are sampled, but the configured PostgreSQL pool does not expose a queue-depth metric. See [pointer profile](../performance/SCENE_REALTIME_PROFILE.md#ephemeral-pointer-profile). The repository remains a single-instance, best-effort delivery service. A packet already queued to a transport cannot be recalled after access changes. [Closure plan](../releases/V0.1.1_CLOSURE_PLAN.md)
